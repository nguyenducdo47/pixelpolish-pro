# Internationalization (content + UI)

## Purpose

Support multiple languages for **portfolio content** (JSON per field) and **application UI** (Laravel lang files + Filament), plus admin-configurable enabled locales.

## Business Rules

### Content locales (portfolio data)

- Translatable fields stored as **JSON objects** keyed by locale code, e.g. `{"vi":"...","en":"..."}`.
- Read path: `HasLocaleText::localeText` picks: requested locale → catalog default → first value.
- HTML fields use `localeHtml` → `RichText::html` (plain text wrapped in `<p>`, editor state rendered).
- List fields (`highlights`): `localeList` — must not be editor state arrays.
- **Required** validation in `LocaleTabs` applies only when editing the **catalog default** locale tab.

### URL locales (public site)

- Pattern: `[a-z]{2}(?:-[a-z]{2})?` in routes.
- Disabled locale in URL → **404**, not redirect.

### UI locales (Studio/Admin)

- `UiLocale`: session key `ui_locale`; candidates include query `?locale=`, path segment, session, fallback `vi` if enabled.
- Public portfolio URL sets UI locale via `SetLocale::remember` (same code as content locale for that request).
- Password reset emails use `UiLocale::current()` at send time.

### Catalog

- `locales` table: `code`, `name`, `native_name`, `is_enabled`, `is_default`, `sort_order`.
- `LocaleCatalog::defaultCode()`: first `is_default` among enabled, else first enabled, else `vi`.
- In-memory memo cleared on `Locale` model saved/deleted and in `LocaleSeeder` (`LocaleCatalog::forget()`).

## Workflow

### Authoring

1. Editor selects active locale in `LocaleTabs` (`_locale`, not dehydrated alone).
2. Visible inputs bind to `_current.{field}`; on locale switch, current values merge into hidden JSON bag `{field}`.
3. Wizard sync merges `_current` into bag using `PortfolioWizardSync::applyLocaleInputs`.

### Reading on site

1. URL `{locale}` passed to presenter.
2. Each localized field resolved with that locale code.

## Data

- `locales` table (admin-managed via `LocaleResource`)
- JSON columns on `profiles`, `projects`, `skill_categories`, etc. (see migration)

## Source of Truth

- Read resolution: `app/Support/HasLocaleText.php`
- Form UX: `app/Filament/Forms/LocaleTabs.php`
- Wizard merge: `app/Services/PortfolioWizardSync.php` (`applyLocaleInputs`)
- Catalog: `app/Support/LocaleCatalog.php`, `app/Models/Locale.php`
- Public gate: `app/Http/Middleware/SetLocale.php`

## Important Edge Cases

- Empty enabled locales collection → LocaleTabs falls back to hardcoded `vi` object.
- Skill **names** are plain strings (not localized JSON) — only descriptions use locale bags.
- `RegisterRequest` lowercases username; locale codes should be lowercase in URLs.

## Related Files

- `lang/en/panel.php`, `lang/vi/panel.php`

## Common Mistakes

- Storing editor TipTap state dict without converting via `RichText::toStoredString` before save.
- Adding a new translatable field without JSON cast on model + LocaleTabs in forms + presenter mapping.
- Using `app()->getLocale()` on public read without passing route locale into presenter (presenter receives explicit `$locale` — good).

## Verification

- Default seed: `LocaleSeeder` creates `vi` (default) and `en`, both enabled.
